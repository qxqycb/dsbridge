# deepseek web bridge

用网页版 DeepSeek 当 agent 的脑子，本地工具当手脚。不要 API key。

浏览器那边只靠一个插件：你自己的 Edge 正常开着，插件在 `chat.deepseek.com` 标签页里
打字、等回答、把文本回传给本地服务。本地服务跑工具循环。**没有任何进程去接管或启动你的浏览器。**

## 工具

模型每轮回一个 JSON 对象，调一个工具。`write` 和 `edit` 另加围栏块，正文不放进 JSON：

```json
{"tool":"ls","arg":"."}
{"tool":"glob","arg":"**/*.mjs"}
{"tool":"grep","arg":"regex"}
{"tool":"read","arg":"path"}
{"tool":"read","arg":"path","offset":600,"limit":80}
{"tool":"write"}              再加一个围栏块，首行是 # path: 文件名
{"tool":"edit"}               再加两个围栏块：先原文，后替换文本
{"tool":"run","arg":"python","args":["tool.py","check"]}
{"tool":"run","arg":"python","args":["-"],"stdin":"print(1)"}
{"tool":"skill"}
{"tool":"skill","arg":"名字"}
{"tool":"mcp"}
{"tool":"mcp","arg":"服务器/工具","args":{}}
{"tool":"ask","arg":"用哪个名字？","options":["a","b"]}
```

**`read` 支持分页。** 不加 `offset`/`limit` 时最多返回 8000 字符，**并且会明说截断在哪、
怎么接着读**（给出可直接复制的下一次调用）。加了 `offset`/`limit` 则按行返回、带行号。
以前是静默截断 —— 模型看不到下一段，只能写个脚本按行打印，几乎每次调试都要多建一个文件。

**`read` 有 4MB 的硬上限**，超过就拒绝。这是防崩不是省上下文：它先把整个文件读进字符串
再切窗口，所以窗口并不能绕过它。`grep` 一直有大小闸（200KB 就跳过），`read` 一个都没有，
一次 `{"tool":"read"}` 打在几百 MB 的日志上就能把服务拖死。超大文件该用 `run` 脚本只打印
需要的那一段。

**`run` 支持 stdin**，短脚本从管道进：`args:["-"]` + `stdin`。`-c`/`-e` 内联代码在
Windows 下换行会被吃、长度还有上限，所以这条路是给临时验证用的。

**一次只发一个工具调用。** 一条回复里若有多个，只有最后一个会执行，其余被丢弃 ——
现在会明确告诉模型丢了几个，否则它会以为自己已经派发了活。

`edit` 要求 `old` 与文件逐字节相同、且在文件里只出现一次；否则报错并说明原因，
模型据此重试。它存在的意义是**改一行不用回整个文件** —— 在聊天驱动的循环里，
这是省上下文和减少改错的关键。

**改文件之前必须先看过它。** `edit` 和 `write` 会检查两件事：这个文件**被 read 过**（或者这个进程自己
刚写过），以及**从读过到现在没变过**。没看过就拒，并给出可以直接复制的 `read`；变过也拒，因为模型
手上的"原文"已经不是文件里的原文了 —— 另一个 agent、你自己、或者一次 `run` 都能在中间改掉它。
新建文件不受这条限制（没有原文可猜）。代价是一轮 read，收益是"照着记忆改"和"拿过期原文改"这两类
错**在动手之前**就被挡住，而不是变成一次静默的错误写入。

工具报错不会中断循环：错误文本会带回给模型让它自己纠正。所以提示词里写了
「以 ERROR 开头的回复是工具失败，读懂它再改」。

**`run` 是受限的执行**：只允许 `python` / `python3` / `py` / `node` 四个解释器，
不经 shell（所以没有管道、重定向、`&&`），30 秒超时，输出截断到 4000 字符，
工作目录锁在工作区内，脚本路径也走同一套越界检查。

**输出被截断时，全文不丢。** 超过 4000 字符就把完整输出移进 `.spill/`，回给模型的是
开头 + 结尾 + **那个路径**，`read` 加 `offset`/`limit` 就能看被切掉的中间段。以前这里是直接
删掉：想看你被切掉的那一段，只能改脚本重跑一次，赌它这次打印得少一点。`.spill` 只留最新
20 份，按文件名（时间戳打头）排序淘汰，不进 `ls`/`grep` 的结果里。

它存在的意义是**让循环能自己验证**：没有它，模型改完代码只能说"请你手动跑一下"，
你永远是它的 CI。有了它，`python tool.py check -` 这类验证它能自己做。

**`skill` 是按需读取的规则文件**：`skills/<名字>.md` 一个文件一条规则。不带 `arg` 列出来
（名字 + 文件首行说明），带名字才读进上下文。所以常驻提示词不必变长，加一条规则也不用改
`bridge.mjs`。首行写说明，别重复文件名，否则列出来是「名字 — 名字」。

**`mcp` 用你自己配的 MCP 服务器。** 在 `mcp.json` 里写服务器，重启服务，它们的工具就能用了：

```json
{"servers":{"fs":{"command":"npx","args":["-y","@modelcontextprotocol/server-filesystem","."]}}}
```

`{"tool":"mcp"}` 列出「服务器/工具」，`{"tool":"mcp","arg":"fs/read_file","args":{"path":"x"}}` 调用。
协议就是 stdio 上的逐行 JSON-RPC（`initialize` → `notifications/initialized` → 请求），
一次调用起一个进程、用完关掉 —— 没有常驻进程要收尸。**配置只在服务启动时读一次**，
所以运行中改 `mcp.json` 不会生效，要人重启：**模型可以调用已配置的服务器，但不能自己装一个**。
这条是刻意的 —— `run` 只放四个解释器，而 MCP 的 `command` 是任意程序，那份文件就是允许清单。

**MCP 需要双向管道**，所以在不允许管道子进程的沙箱里它起不来（会明确报 EPERM，而不是静默失败）。
`check-mcp.mjs` 遇到这种情况会打一行 `SKIP` 并退出 0，不会伪装成通过。

## 工作区：只动你指定的那个文件夹

**左栏顶上那个输入框就是工作区**，打字回车（或点「应用」）就切过去。它是**工具唯一能改的地方**：
`ls`/`glob`/`grep`/`read`/`write`/`edit`/`run` 的每一个路径都过同一个 `safe()`，而 `safe()` 是拿
工作区做基准的 —— 所以这不是九处要记得加的检查，是**一个函数**，换工作区就是换那个基准。

- 默认是**桥自己所在的文件夹**（以前的行为，没设过的人感知不到变化）。
- 选择会写进 `workspace.txt`（和桥放在一起，不进你的仓库，已 gitignore），重启还在。
  `BRIDGE_WORKSPACE` 环境变量优先级更高，给脚本用。
- 路径必须是**已存在的文件夹**，否则原样报错不改（否则后面每个工具都会 ENOENT 而没人提原因）。
- **任务运行中不给换**：那一轮所有路径都已经按老工作区解析过了，一半在一个文件夹一半在另一个，
  比等几秒糟得多。
- 桥自己的东西**不跟着走**：`.sessions/`、`skills/`、`mcp.json`、`ui.html` 留在桥的目录里。
  工作区里只留 `.spill/` 和 `.run-*.tmp` 这两个（模型要能 `read` 回 spill 文件，而 `read` 是按
  工作区解析的），两者都在 `ls`/`grep` 的跳过名单里。

**两条仍然能出去的路，说清楚**：一次**经人批准的**越界调用（要点一下），和 `run` 里的脚本
（脚本正文能写到进程能写的任何地方 —— 跑代码的固有边界，README 里一直写着）。
除此之外，不点、不跑脚本，就出不去。

## 人在回路里：提问、越界、权限

三件事，一个通道。模型要问、或者要动工作区外的东西，控制台就出现一张卡片，你答完它继续。

**`ask` 是阻塞的。** `{"tool":"ask","arg":"问题"}` 加上 `"options":["a","b"]` 会给你几个按钮。
这时候回合槽是空的（模型正在等工具返回，不是在等一轮回答），所以**协议一个字都不用改**：
你的答案就是工具结果。**停止**和**重置**会把悬着的问题一起放开 —— 否则一个问题能把整个桥卡住。

**模式是你在控制台右上角选的**，模型没有任何工具能碰它：

| 模式 | 行为 |
|---|---|
| 只读 | `write` / `edit` / `run` 一律不发。看可以看，动不行 |
| 工作区（默认） | 工作区内随便动；工作区外**每次问一次** |

**没有"全权"模式**，这是故意的：一个常驻的"什么都放行"离一次没人看见的误操作只差一次点击，
而批准卡已经把真实需求按次覆盖了 —— 要出工作区，就一次一签。

**越界是一次一放。** 路径闸拒绝时会在错误里说明怎么申请（那是模型唯一能学到这件事的地方）：
同一次调用加 `"outside":true` 和 `"why":"要它干什么"`，控制台弹出批准卡，你点允许就执行这一次，
下一次照样被拦。**这个判定只在 `safe()` 里做一次** —— 九个工具各自加参数，早晚有一个被忘掉。
同样，只读模式那道闸在循环里，不在每个工具里，所以以后新加的工具自动被它管住。

**不加的东西**：通用 shell。那等于把整台机器交出去，而且网页版模型在长命令上容易跑偏。
需要新能力时优先加**具体工具**（像 `run` 这样参数化、可校验的），而不是放开一个 shell。

## 文件

| 文件 | 作用 |
|---|---|
| `bridge.mjs` | 本地服务 + 工具循环 + 工具表。零依赖，只用 `node:http` |
| `check-protocol.mjs` | 浏览器无关的协议回归检查 |
| `md.js` | 客户端的 markdown 解析：块 + 行内片段，纯函数、不碰 DOM，所以 node 里能直接测 |
| `ext/manifest.json` | 插件清单（MV3） |
| `ext/background.js` | service worker，轮询本地服务。https 页面不能直连 `http://127.0.0.1`，必须它来转发 |
| `ext/popup.html` + `popup.js` | 点图标弹出的面板：状态、开关、最近事件 |
| `ext/content.js` | 页面侧：注入文字、等回答结束、回传正文（排除思考体） |
| `skills/<名字>.md` | 按需读进上下文的规则文件，由 `skill` 工具列出和读取 |

## 起

1. `edge://extensions` → 打开"开发人员模式" → "加载解压缩的扩展" → 选 `D:\xmkf\web-bridge\ext`
   （**只在插件代码改动后才需要重载**，日常不用）
2. 开一个 `chat.deepseek.com` 标签页，**登录好**
3. 点一次工具栏上的插件图标 → 面板里点 **"启动"**。之后它会一直轮询，不用再点
4. 起本地服务，**一次就够，让它常驻**：

```sh
cd D:\xmkf\web-bridge
node bridge.mjs
```

5. 浏览器打开 **http://127.0.0.1:8791** —— 这就是客户端

## 客户端

三栏：左边会话历史，中间对话流，下面输入框。

**样式抄的是同一套设计令牌**：颜色值直接来自 harness 的
`packages/client/ui-theme/src/styles/design-platform.css`（`--dsw-static-neutral-bluish-*`、
`--dsw-static-deepseek-*`、`--dsw-alias-*`），所以这里的一个颜色可以拿去和那个文件对，不用猜。
**默认跟随系统的亮/暗**（`prefers-color-scheme` + `color-scheme`，UA 自己的滚动条和控件跟着走）。
正文用 UI 字体，机器写的东西（围栏代码、工具输出、日志行）用等宽 —— 代码字体栈故意不留裸
`monospace` 尾巴，Windows 上中文会掉到 SimSun。圆角沿用他们的量级：输入框 16px、卡片 12px、按钮 8px、
模式按钮是胶囊。

细节上：**每条任务是一节**（上面一条细线 + 更多留白），因为一个对话里现在有好几条任务，记录得说清
每节从哪开始；工具卡片折起来有个会转的箭头，悬停会**轻轻抬起一点**；diff 的增删行是**带底色的**，
不只是字变色；回复里的链接和粗体有自己的规则（否则浏览器默认那抹蓝紫在暗色下很跳）；
**新内容淡入上浮**（回看历史时不放动画，一百多条事件会整体闪一下）；内容限宽 880px 居中——满屏宽度下段落要横穿一整个 27 寸屏，眼睛会丢行；右下角有个**回到最新**的圆钮，
只在往上滚动时出现；输入框有**中性色**的焦点边框和光晕、光标跟随正文色，上面一层很淡的上浮阴影
（蓝色按要求删掉了；注意文字输入框**在任何方式获得焦点时都匹配 `:focus-visible`**，点一下也算，
所以那圈蓝色焦点环必须在输入框上单独关掉，否则它立刻就回来）；
**代码块自己有复制键**（悬停才亮，那才是真正要复制的东西）；运行中状态灯是**缓慢呼吸**；
有 `:focus-visible` 焦点环和 `prefers-reduced-motion` 的兜底（连平滑滚动一起关）。
`color-mix()` 让半透明色跟着令牌走，不用另造 rgba。

| 区域 | 说明 |
|---|---|
| 左栏 | 磁盘上的**对话**（`.sessions/*.jsonl`，一条一行），上面有过滤框，点一条回看 |
| 中间 | 你发的任务、每轮工具调用（可折叠卡片，显示参数和结果）、模型的回答 |
| 底部 | 输入框 + 发送 / 停止 / 新对话 / 清空显示 / 检查页面 |

**左栏那些顺手的东西**：过滤框是本地 substring（一百多条对话的时候，这是列表和菜单的区别）；
正在写的那条对话在时间旁边写「进行中」；**标签页标题会变**——`⚠ 等你回答` / `运行中…`，因为跑着的
任务卡在一个问题上，和在思考，从别的标签页看是一模一样的。

**复制**：每条回答和每张工具卡右上角有一个「复制」（悬停才亮，平时很淡），一次点击全文进剪贴板。
`navigator.clipboard` 需要安全上下文，`127.0.0.1` 算，所以没有回落分支。

**左栏一行是一个对话，不是一条消息。** 发第二条任务**追加**到当前那条，中间那块也不清空 ——
以前每条任务都铸一个新会话文件、客户端还把记录擦掉，所以每发一条都像新开一个对话。
只有**新对话**会开新的一条。每条任务仍然在文件里写自己那行 `task`，所以每次是从哪儿开始的
在盘上都有；那一行的标题取的是这个对话的第一条任务（像聊天应用那样，不随后续消息改名）。
`/status` 里的 `sessionId` 就是当前这条对话的 id —— **会话的身份是 id，不是标题**：任务会追加到
一条已存在的记录里，拿标题去认身份会认错人。

**回答按 markdown 渲染**：代码块、列表、引用、行内代码、粗体都成形状。渲染器在 `md.js`，页面
import 它。它只产出文本节点，所以回复里的标记会被**显示**，不会被当成 HTML 执行。日志行和工具
卡片照旧是等宽纯文本。**没有加聊天气泡** —— 曾经试过给「你」「它」加标签和左边框，用户要求改回去，
只保留换行和 markdown。

**回复的换行是抓取侧的问题，不是显示侧的。** `ext/content.js` 一度在**脱离文档的克隆节点**上读
`innerText`，而没被渲染的元素上这个属性会回退成 `textContent` —— 它把 `<p>` 和 `<p>` 直接粘连，
于是模型写的段落换行全丢，整篇回复变成一行。指纹很好认：**带代码围栏的回复有换行**（那些换行是
桥自己插的文本节点），**纯散文的回复一行到底**。现在 `blockText()` 走一遍树补回块级换行。
这条改动在 `ext/` 里，`CONTENT_VERSION` 随之抬升（准确值看 `bridge.mjs` 顶部，别写死在这里 ——
它漂过两次）：不重载插件的话界面会红字提示版本不一致，而不是继续用旧脚本。

**发送按钮只在输入框附近找，不在整个页面里找。** 以前 `SEND` 里那两条按 class 匹配的兜底
（`ds-button--primary` / `ds-button--filled`）笼统到足以命中**侧栏的"新对话"按钮**。点中它就会
开一个新对话，而且它同时把输入框清空 —— 发送逻辑把这读成"发成功了"。于是消息丢掉、任务跑到
另一个对话里，全程没有一个报错。现在的取舍是：找不到就**大声失败**（`--probe` 会列出输入框
周围的按钮），而不是猜一个点下去。另外新增一条判据：一轮结束后比对**对话 id**，不是比对地址 ——
空白对话在发出第一条消息后会拿到 id，那是正常的；从一个 id 跳到另一个（或跳回空对话）才是
"点错了"，这时直接报错。

- **Enter** 发送，**Shift+Enter** 换行（**Ctrl+Enter** 也发送，老习惯不用改）。输入框随草稿长高，
  封顶 320px，超过就自己滚。中文输入法拼字时按回车是在选词，不会发出去；按住回车也不会连发
- 右上角两个按钮是**权限模式**（只读 / 工作区），见上一节。它由人在页面上切换，模型够不着
- 模型提问或申请越界时，中间会插一张卡片（问题 + 可选按钮 + 输入框）；状态灯变成**等你回答…**。
  点过之后卡片变灰锁住，重复点会被 409 挡下（页面刷新过也一样）
- **停止** 中断当前任务：服务端标志在轮次之间生效，同时通过 `/status` 通知扩展点页面的停止控件
- **新对话** 武装下一条：它会在 DeepSeek 那边开一个新对话，而不是接着上一个，**同时**在控制台
  开新的一条记录。发出去就解除武装（被 409 拒绝时不解除）。默认是**接着上一个对话** ——
  模型那边带着上文，控制台这边也还是同一条记录
- **清空显示** 只清这个页面的记录，永远不碰网页里的对话，也不动左栏的记录
- 状态灯：**就绪** / **运行中…** / **等你回答…** / **正在停止…** / **等插件** / **本地服务已断开**

页面用 **SSE**（`/events`）接收事件，不轮询。事件同时写进 `.sessions/<时间戳>.jsonl`，
所以关掉标签页不会丢正在跑的任务，重启服务后历史还在。

**写盘走一条链，链就是检查点。** 两个理由：`appendFile` 并发落盘可能乱序，而**日志的顺序就是
回放的顺序**；另外循环可以在**模型请求和改文件之前**等这条链排空，于是崩溃时不会留下"记录里
没有、但其实已经跑过"的调用。以前是发了不管，两种错都不会报，只是回放与实际悄悄不一致。
（模型请求之前不等 —— 模型的上下文是网页，不是这份日志，等了没有意义。）
`check-events.mjs` 现在逐事件比对**流里收到的**和**文件里存下的**，从 `start` 开始，
第一处不一样的会指名道姓。

「从 `start` 开始」不是偷懒：控制台在开会话之前就记了一行任务文本，那一行**注定只在流里**，
因为没有文件可写。这条边界是检查写出来之后才发现的，不是设计出来的。

旧的简易控制台仍在 **`/legacy`**。

**没变的东西不用动**：插件代码没改就不用重载，页面没崩就不用刷新，任务从客户端发就不用开终端。

命令行方式仍然保留，方便脚本化：

```sh
node bridge.mjs "任务"        # 跑一次然后退出
node bridge.mjs               # 常驻 + 控制台（推荐）
```

## 怎么知道它在工作

点插件图标看面板：

- **轮询中** + 图标上有绿色小字 → 在等任务
- **已停止** → 点"启动"
- 图标显示 **off**（红色）→ 本地服务没起，或端口不对
- 面板下方是最近 20 条事件，每轮任务都会记一行
- 停止后面板不再刷新，记录留着方便复制；要清空点面板底部的"清空记录"

不用开 DevTools。

## 排查

三种模式：

```sh
node bridge.mjs "任务"            # agent 循环：模型用 ls/read/write，最后给总结
node bridge.mjs --ask "问题"      # 不加协议，原样发一句，拿回原文。逃生口
node bridge.mjs --task-file p.md  # 任务从文件读，绕开命令行长度上限
node bridge.mjs --probe           # 量选择器，不改任何东西
```

agent 模式第一行会打印实际收到的任务（`task: 28 chars | "..."`）。如果模型说
"没有任务"，先看这一行 —— 任务文本在本地就丢了，不是模型的问题。

`--task-file` 是给长任务用的。命令行长度有上限，超了会**静默截断**，
表现和"模型读不懂"一模一样。

`--probe` 打印 `content.js` 里 `INPUT` / `SEND` / `REPLY` 实际命中了什么，以及
输入框往上 5 层里的所有按钮。改 `ext/content.js` 顶部的候选数组，然后在
`edge://extensions` 里点插件的"重新加载"，**再刷新页面**。

**回答里混进"我们需要回答…"这类独白时**：`REPLY` 抓错了元素。**回答体和思考体共用
`.ds-markdown` 这个类名**，区别只在祖先 —— 思考体裹在 `ds-think-content` 里。
`pickReply()` 靠排除它来分辨，并且锚定在最后一个 `ds-message` 上，
以免把你自己刚发出去的提问当成回答。改这里之前先跑 `--probe` 看
`pickedHead`：它应该是**答案的开头**，不是"我们需要…"。

`ext/content.js` 顶部有一段 **verified DOM baseline**，是最后一次确认可用的真实
DOM 快照。前端改版后，重跑 `--probe`，跟那段注释对比 —— 第一处不一样的地方就是
断点。注意 `_` 开头的类名（`_27c9245`、`_52c986b`）是构建哈希，每次发版都变，
永远不要拿它当选择器。

agent 模式每轮都会打印耗时（`[0] +3.2s <- "..."`），卡住时能看出卡在第几轮。
**那个数字是"这一轮回复等了多久"**（含模型生成 + 页面收尾判定），不是从任务开始算的 ——
以前是后者，于是一张 `ls` 的卡片会写「12.2s」，看着像工具很慢。

**收尾等待会单独记一行**：`[页面] 回复收尾等了 8.2s（grace，320 字符）`。抓取侧在正文不再变化后
还要判定"答完了"，两条出口——看到消息上的操作栏就等 1.5 秒，**没看到就退到
`2s + 每 1000 字符 2.5s`（上限 30s）的静默窗口**。所以如果操作栏的选择器失效了，每一步都会白等
至少 2 秒，而服务端看它和"模型很慢"一模一样。这行日志就是用来区分这两件事的：
`action-bar` 是正常路径，常出现 `grace` 就说明该去修检测器了（`--probe` 的
`markers.actionButtons` 答完之后还是 0，是同一个信号）。

**每一轮发出去的东西也记下来了**，在耗时那行之前一行：

```
[req] 2471c dbd7fbdef449 "…Never emit <system> tags…\n\nTask: session check task"
```

长度 + 摘要 + 尾部 200 字，`kind` 是 `request`，跟别的日志一样进 `.sessions/*.jsonl`。
以前只记回复、不记请求，于是「页面没回答」和「我们什么都没发出去」长得一模一样 ——
而空提示词或被截断的提示词正好制造那种沉默。摘要一样就是同一段请求发了两次，
跨轮次、跨重启都认得出；光靠长度和尾部认不出来，因为第一步之后的每轮都是
一个大小相近的 `RESULT:` 外壳套着不同内容。摘要只用来对照，不是校验。

页面控制台里 `window.bridgeTurn("你好")` 可以手动跑一轮，不经过本地服务。

端口默认 8791，被占就换：`$env:BRIDGE_PORT=8792`（两边都要）。

环境变量（都可选，用于调参或测试）：

| 变量 | 默认 | 作用 |
|---|---|---|
| `BRIDGE_PORT` | 8791 | 本地服务端口 |
| `BRIDGE_TURN_TIMEOUT` | 600000 | 单轮等待上限（毫秒） |
| `BRIDGE_MAX_STEPS` | 24 | 一次运行最多几轮，到顶会显示提示 |
| `BRIDGE_MAX_REPAIRS` | 3 | 一次运行最多容忍几次「像工具调用但解析不了」的回复 |
| `BRIDGE_RUN_TIMEOUT` | 30000 | `run` 工具的单次执行上限（毫秒） |
| `BRIDGE_MCP_TIMEOUT` | 20000 | 一次 MCP 请求的上限（毫秒），到点杀子进程 |
| `BRIDGE_MCP_CONFIG` | `mcp.json` | MCP 配置文件名，检查用来自带一份、不碰你的 |

**撞到步数上限会明确显示** `⚠ (step cap reached after ...)`。以前这条提示被丢掉，
一个跑光的运行和一个跑完的运行看起来一模一样。

**一直修不好的坏 JSON 会提前收摊。** 回复里有 `{"tool":...}` 但解析不了时，会回灌原因让
模型重发；这件事以前没有上限，于是一个改不好的回复能把 24 轮全烧光，最后死在步数上限上 ——
看起来像"轮次不够"，其实是"它始终没吐出合法 JSON"。现在连续 `BRIDGE_MAX_REPAIRS` 次就
报错退出，一轮不多问。

健康检查（会占用当前任务直到回答，重复调用拿到的是同一个任务）：

```powershell
curl.exe http://127.0.0.1:8791/job    # 挂 25 秒，返回 {} 或一个任务
```

## 检查

```sh
node bridge.mjs --selftest      # JSON 解析、路径逃逸、每个工具、协议解析
node check-protocol.mjs         # 长轮询、排队、错误传播、超时恢复、控制台端点
node check-codetext.mjs         # 代码块提取（页面把代码拆成逐行 token span）
node check-edit.mjs             # 两围栏 edit 协议，真写文件验证
node check-run.mjs              # run 工具：白名单、超时、输出上限、越界拒绝
node check-sessions.mjs         # 会话存盘、列出、回看、id 越界拒绝
node check-events.mjs           # SSE 事件流：hello/start/log/tool/end/idle；客户端接线 + 真的跑一遍渲染
node check-markdown.mjs         # md.js 的块与行内解析，含"不许出现非 http(s) 链接"
node check-mcp.mjs              # MCP：列出、调用、错误、超时、超大回复落盘（沙箱里会 SKIP）
```

这些都不碰浏览器，随时能跑，提交前全跑一遍。`check-events.mjs` 里有一个最小的 DOM 桩：它把
`ui.html` 的 module 脚本**真的执行起来**，喂一段带围栏的回复给渲染函数，再断言元素树。编译检查
抓不到返回值写错这类问题 —— 加这个桩之前，`box.append(x).append(y)`（`append()` 返回 undefined）
让回复整段不显示、回看还从第一处回答起截断，而所有检查都是绿的。

**文件内容一律走围栏，绝不放进 JSON。** 两个原因：JSON 字符串里每个引号都要转义
（模型改代码时天天写 `"-"`，一次漏转义整条回复就废了），而且页面会折叠内联文本
里的连续空格，缩进会被毁掉。所以协议是：

- **`write`**：一个围栏，首行 `# path: 文件名`，其余是文件
- **`edit`**：两个围栏，第一段是要找的原文，第二段是替换文本

**改 `ext/` 之后**：重载插件 + 刷新页面，然后点控制台"检查页面"，
确认 `contentVersion` 和服务端的 `contentVersion` 一致（见 `/status`）。
对不上就是旧插件还在跑，此时任何报错都别信 —— 先把它换掉。

## 已知限制

- 站点的 DOM 一改版就废，`ext/content.js` 是唯一的维护面
- 没有历史重放：上下文全靠网页会话自己，顶到长度上限就完蛋
- 自动化访问违反 DeepSeek 用户协议，账号有风险
- 一次只支持一个轮询中的 turn（单个 `waiting` 槽位）
- 工具结果以 `JSON.stringify` 转义后发给模型，所以模型看到的是
  `"bridge.mjs\ncheck-protocol.mjs"` 这种 JSON 字符串，而不是原始多行文本。
  好处是文件里的引号不会再让模型输出非法 JSON；代价是多一层转义，会略微消耗
  模型的注意力。若发现模型对转义文本理解变差，改成原文直传并处理引号即可
- **文件内容走代码块，不走 JSON**。页面会把内联文本里的连续空格折叠成一个，
  所以塞进 JSON 字符串的代码缩进会被毁掉（4 个空格变 1 个），生成的脚本一行都
  跑不了。代码块的 `<pre>` 保留原始文本，`write` 因此改成
  `{"tool":"write","arg":"x.py"}` 加一个围栏块。代价是模型得遵守两种格式
- 开新对话靠**后台把标签导航到根路径** `https://chat.deepseek.com/`，不是点页面里的按钮。
  页面那个"新对话"是纯图标，既没 aria-label 也没文字，选择器抓不住。由后台导航还有
  个好处：导航发生在发消息**之前**，所以不会出现"卸载 content script 导致消息通道断掉"
  那个坑。默认**不**导航 —— 任务接着上一个对话跑，这样模型能带着上文接着干；
  只有按了面板上的"新对话"，或者命令行 `node bridge.mjs "任务"`，才开新的，
  这时标签会闪一下重载
- 深度思考的独白会一起被抓回来，占用网页上下文预算。想干净就在界面上关掉
- 版本 0.1
